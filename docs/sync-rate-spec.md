# シンクロ率システム仕様書 v1.0

信頼度システムを置き換える新仕様。**数値はすべてシミュレーション検証前の暫定値**であり、検証後に確定する。

---

## 1. 設計転換の経緯

### 旧・信頼度の問題

カバー行為（弟の好みを却下してデッキを整える）が信頼度を下げ、次のプレイのペナルティになる構造だった。**主軸の行為に罰を課している**ため、裁定のたびに損失回避を考えさせる重い体験になっていた。テストプレイでも「意味を感じにくい」と評価された。

### 新・シンクロ率の方針

- **罰から積み上げへ。** 弟の好みに沿う選択が積み上がり、ボーナスが得られる。却下しても下がらない（上がらないだけ）
- 損失フレームから獲得フレームへの転換。判断の構造（支持か却下か）は変えず、感情の符号だけ反転させる
- 世界観上の根拠：子供にカードバトラーの力が宿る世界なら、子供とカードの相性（シンクロ）があるのは自然。カードプール＝チーム、デッキビルド＝試合ごとのスタメン選び
- 300〜500円帯の軽いゲームとして、理詰めのリソース管理より気持ち良さを優先する。アッパー調整の大味さは許容する

## 2. 基本仕様

| 項目 | 値 | 備考 |
|---|---|---|
| レンジ | 0〜100 | |
| 初期値 | **0** | 積み上げ型のため0開始（旧信頼度の50とは異なる） |
| 段階 | 5段階・20刻み | 0-19 / 20-39 / 40-59 / 60-79 / 80-100 |
| 表示 | 段階表示（数値マスク） | 旧信頼度と同じ方針。原則4 |
| スコープ | 1周（アーケード1回）で完結 | 周の開始時に0へリセット |

### 上昇

- **受動介入で弟の第一希望と一致する選択をした時のみ上昇する。** 上昇量 **+8**（暫定）
- 第一希望は非表示のため、上昇条件は実質「読みが当たったか」。プレイヤーの読みという判断がそのまま成長に変換される
- 却下（希望と不一致の選択）は変動なし。下降は存在しない
- 一目惚れ発火時・アドバイス由来ピックでは変動しない（受動介入ではないため）

### 減衰（試合間クールダウン）

- **各試合終了後、現在値の30%を失う**（×0.7、暫定）
- **床は絶対値20**（段階2の下限）。一度段階2に達したら、それ未満には減衰しない。序盤の積み上げが完全消失しない保証
- フレーバー：試合に向けてテンションとシンクロを高め、試合後は少しクールダウンする。不自然さのない持ち越し理由付け

### 想定される推移（1戦あたり受動介入6回の場合）

| 読み一致率 | 1戦目末 | 2戦目ビルド末 | 3戦目ビルド末 | 切り札解禁 |
|---|---|---|---|---|
| 6/6（全一致） | 48 | 81.6 | 100 | 2戦目から |
| 5/6 | 40 | 68 | 87.6 | 3戦目のみ |
| 4/6 | 32 | 54.4 | 70.1 | なし |

読みの精度で切り札の解禁タイミングが変わる勾配になっている。この形が検証の目標値。

## 3. ボーナス（二層構造）

**恒常効果の階段**が常時の手応えを作り、**最大時のみの切り札**が積み切る動機を作る。減衰で段階5から落ちると切り札権を失うため、最大値の維持そのものがゲームになる。

### 構造

- 恒常効果は「条件の緩和」と「付与の追加」の二軸で階段を作る。**キャラのデッキタイプを増幅する方向**に設計する（単純弟のアグロが、シンクロが上がるほどアグロとして完成していく）
- **付与は確率発動とする。** 該当カードを場に出す際に抽選し、成功時のみキーワード・修正が付く。発動率はシンクロ段階に連動し、**段階5のみ100%（確定）**
- 確率化の設計意図：①確定付与だとビルドの最適解を書き換えてしまい欠損診断と干渉するが、期待値の判断に弱めることで診断の軸を守る ②絆は装備ではなくブレるもの——不発は「運の不運」ではなく「シンクロがまだ足りない」証拠として、成長の物語に組み込まれる（段階が上がるほど確率が上がるため）③2pick不慣れな初心者にも上振れによる勝ち体験を供給する。対人DCGでは禁じ手の確率上下振れが、一人用ゲームでは難易度緩和と演出の美点に反転する
- 抽選はカードごとに独立（プレイ時判定）。試合単位の一括判定は分散が小さすぎ、不発試合でシンクロが空気になるため不採用
- 適用判定のタイミングは**そのカードを場に出した瞬間**。戦闘開始時のシンクロ段階を参照する（戦闘中は段階変動しない）
- 付与はすべて既存7語の範囲。エンジンに追加されるのは「プレイ時に段階と確率を見て該当札へキーワード・修正を付ける」処理1本のみ（原則3遵守）
- 段階ごとの内容・発動率は `data/children/` のキャラデータに定義（原則2遵守。エンジンは共通、差分はデータ）

### 単純弟のボーナス表（暫定）

| 段階 | シンクロ率 | 恒常効果 | 発動率 |
|---|---|---|---|
| 1 | 0-19 | なし | — |
| 2 | 20-39 | コスト1のカードに速攻付与 | 25% |
| 3 | 40-59 | コスト2以下に速攻付与 | 50% |
| 4 | 60-79 | コスト2以下に速攻付与＋強化+1 | 75% |
| 5 | 80-100 | 段階4の効果＋**切り札指定 解禁** | **100%（確定）** |

段階5のみ確定である理由：「最大シンクロ＝完全な絆＝必ず応える」という物語の頂点を、確率の消滅として表現する。積み切る動機の担保でもある。

他キャラの方向性（将来実装の参考）：気弱妹＝低コストに守護／聡明弟＝スペルコスト減または任意タイミング切り札／いとこ＝高コストにダメージ付与など。同じ「条件＋キーワード」の文法で全キャラ書ける。

## 4. 切り札（ディスティニードロー）

旧・主人公補正（v0.2で保留箱入り）の再実装。シンクロ最大時の段階報酬として置くことで、「介入と別系統のシステムを1キャラのために増やす」という保留理由が解消された。絆が奇跡を起こすという平成アニメの様式を、メカニクスの因果として実装する。

### 仕様

| 項目 | 内容 |
|---|---|
| 解禁条件 | デッキビルド終了時点でシンクロ率が段階5（80以上） |
| 指定 | ビルド終了後、デッキ15枚から1枚を切り札に指定する |
| 別枠処理 | 指定札は**表示上デッキに含まれるが、処理上は別枠**。通常抽選対象外となり実デッキは14枚（実質デッキ圧縮の隠れボーナス） |
| 発動条件 | 自分ライフが**7以下**（暫定）になった後の、次の自分ドロー |
| 発動 | ドローが切り札に置き換わり、キャラ固有の付与を受けた状態で手札に来る |
| 回数 | 1試合1回 |
| 指定制限 | なし。重すぎる切り札が腐るのはプレイヤーの読み違いであり、学習の一部。終盤までもつれた試合でだけ重い切り札が輝く賭けも成立する |
| キャラ固有付与（単純弟） | **強化+2＋速攻**（暫定）。data/children/ に定義 |

### 演出要件（バトル演出工程に引き継ぐ）

発動条件を満たしたターンの終わりに溜めの予告（「弟の手がカードに伸びる…」）を一拍入れ、次ターン頭に引く。ディスティニードローには溜めが必須（様式）。

## 5. 関連する変更

### 受動介入頻度のキャラ性能化

旧信頼度が持っていた「受動介入頻度への連動」は**シンクロ率には搭載しない**。頻度はキャラ固定値とし、キャラクター性能の差として表現する（妹は多い、聡明弟は少ない）。単純弟は**50%固定**（暫定）に戻す。

シンクロ率の役割はボーナス軸のみに純化される。役割が混ざらない。

### 対戦相手の強化

シンクロによる成長曲線が入るため、**梯子後半の相手を強くできる**ようになった。boss を正面から強化する（現状は3体ほぼ水平）。「格上に届く理由」をシステムが供給する——悪の組織のボスが強いのは当たり前で、それを子供が超えるのは絆の力。様式とバランスが同じものを指す。

boss の強化内容はシンクロ込みの勝率シミュレーションを見てから決める。

### 旧信頼度実装の扱い

- 5段階・持ち越し・段階表示の実装は流用（数値の意味とラベル文言を差し替え）
- 下降ロジック・却下時の変動・美的スコア係数連動は削除
- デススパイラル対策（床20）は「減衰の床」として意味を変えて残る
- 却下時の反応台詞（「えーっ、そっちなの！？」系）は**残す**。シンクロが上がらなかった事実の提示であり、読みの答え合わせとして機能は不変

## 6. シミュレーション検証項目

1. 読み一致率ごとのシンクロ推移が §2 の目標勾配（全一致で2戦目解禁、5/6で3戦目解禁、4/6で未解禁）に収まるか。収まらない場合は上昇量+8と減衰率30%を調整
2. 恒常ボーナス込みの各戦勝率。特に段階3〜4の速攻付与がrush・wall戦の勝率をどこまで押し上げるか（押し上げすぎるなら付与条件か発動率を絞る）
3. **発動率の体感検証（実プレイ必須）：** 段階4（75%）で不発が連続した試合の頻度と、その時の体験の質。荒れるようなら試合単位抽選（C案）への切り替え、物足りなければ確率引き上げを検討
4. boss をどこまで強化すると「シンクロ高で勝率60〜70%、シンクロ低で30%台」の帯に入るか
5. 切り札の発動率（ライフ7以下に到達する試合の割合）。発動しない試合が多すぎるなら閾値を上げる
6. 受動介入6回/戦の前提が50%固定化後も維持されるか

## 7. 実装影響範囲（見積もり用）

- `src/core/trust.ts` → シンクロ率モジュールへ改修（上昇・減衰・段階判定）
- `src/core/draft.ts` → 変動ロジックの差し替え、受動介入率の固定値化
- `src/core/battle.ts` → 戦闘開始時の恒常ボーナス適用、切り札の別枠管理と発動処理
- `src/core/run.ts` → 試合間減衰の組み込み
- `data/children/tanjun.json` → シンクロボーナス表・切り札付与・固定介入率の追加、旧信頼度係数の削除
- UI → 段階表示のラベル差し替え、切り札指定画面（ビルド終了後）、発動演出（バトル演出工程と統合）
- テスト → 旧信頼度テストの改修＋シンクロ推移・減衰・切り札のテスト追加
